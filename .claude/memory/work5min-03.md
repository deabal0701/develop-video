### 2강과 겹치지 않게 축을 갈랐다 — 이 회차의 핵심 설계

2강(프롬프트, 왜 질문이 절반인가)이 이미 **예시·과정·역할**이라는 프롬프트 기법을 다뤘다.
3강을 "프롬프트 잘 쓰는 법"으로 잡으면 사실상 같은 회차가 된다. 그래서 축을 이렇게 갈랐다:

| | 축 |
|---|---|
| 2강 | **어떻게 물어보나** — 기법 |
| 3강 | **무엇을 건네고 무엇을 내가 지키나** — 업무 장면(문서 작성) |

퓨샷은 두 회차에 다 나오지만 **중복이 아니라 설계다**(스킬 '회차는 독립이다' 절) — 2강은
기법으로, 3강은 "형식은 설명하지 말고 보여준다"는 실무 규칙으로 나온다.

### 컨셉 — 초안이 밋밋한 건 도구 탓이 아니다

**회식 공지 메일 한 장**으로 회차 전체를 관통시켰다. 훅에서 "항상 감사드립니다"로 시작하는
쓸 수 없는 초안을 보여주고, payoff 에서 재료 세 줄이 붙어 살아나는 것으로 회수한다.
추상 개념(컨텍스트)을 이름 있는 장면에 얹는 것이 이 회차의 재미 장치다.

## 걸린 것

**사전 점검이 params 를 "받지 않는다"고 막았다 — 헬퍼로 감싼 q.get 때문.**
preflight 는 html 소스에서 `data-p="이름"` 과 **`q.get('이름')` 리터럴**을 찾아 파라미터
목록을 만든다. 그런데 도식 스크립트를 `const at = (k,d) => parseFloat(q.get(k))` 처럼
헬퍼로 감싸면 **이름이 소스에 문자열로 남지 않아** 전부 오탐으로 걸린다(t1~t5·tterm 12건).

고친 방법 — 스크립트 첫머리에서 이름을 명시적으로 한 번 읽는다:

```js
const P = { t1: q.get('t1'), t2: q.get('t2'), tterm: q.get('tterm') };
const at = (k, d) => { const v = parseFloat(P[k]); return Number.isFinite(v) ? v : d; };
```

점검기를 끄지 않고(`--skip-preflight` 는 TTS 실측 때만 썼다) 템플릿을 고쳤다 —
이 점검은 "조용히 빠지는" 결함을 잡는 마지막 방어선이라 끄면 의미가 없다.
**다음 회차 도식을 쓸 때도 이 형태를 지킨다.**

또 하나 — 검증 중 s1 프레임을 46초에서 뽑고 "termnote 가 없다"고 잠깐 판단했는데,
`tterm=52` 라 아직 등장 전이었을 뿐이다. **지연 등장 요소는 그 시각 이후로 뽑아야 한다.**
