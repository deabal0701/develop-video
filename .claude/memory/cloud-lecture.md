## 제작

"5분 개념 영상으로 클라우드를 설명하라"는 요청. 대상은 **완전 입문자**(IT 비전공자)로 잡았다 —
질문 라운드에서 사용자가 고른 값이다. 그래서 IaaS/PaaS/SaaS 같은 약어를 한 번도 발음하지 않고,
"땅만 빌려 짓기 / 뼈대까지 빌리기 / 가구까지 갖춰진 집에 몸만 들어가기"라는 집 비유로만 풀었다.
AWS·Azure·GCP 같은 고유명사는 5장에 가서야 나온다 — 개념이 서기 전에 이름부터 나오면
입문자는 외울 것으로 받아들이기 때문이다.

구성은 6장 + 도입/마무리. 각 장은 **챕터 카드 → B롤(비유·분위기) → stat 카드(정리)** 순으로
반복된다. 정보를 말로만 흘리지 않고 매 장 끝에 한 장짜리 카드로 묶어 주기 위한 리듬이다.

- 1장 클라우드는 하늘에 없다 — "결국 남의 컴퓨터"라는 한 줄 정의
- 2장 왜 빌려 쓰는가 — 전기 요금 비유(발전소를 짓지 않는다)
- 3장 늘었다 줄었다 — 명절 쇼핑몰, 확장성
- 4장 어디까지 빌릴 것인가 — 집 비유 3단계
- 5장 그래서 어디를 쓰나 — 아마존·MS·구글, 그리고 단점(요금·장애 의존)
- 6장 남의 컴퓨터인데 안전한가 — 입문자가 반드시 묻는 질문

**목소리는 기본값인 edge 의 선희(`ko-KR-SunHiNeural`)를 그대로 썼다.** 이번 세션에서 스킬의
기본 음성을 선희로 명시하는 작업을 먼저 했고(커밋 a401227), 그 기본값이 실제로 적용되는지
겸사겸사 확인하는 자리이기도 했다. `rate`는 +6% — ai-lecture(+8%)보다 살짝 느리게 뒀다.
개념을 처음 듣는 사람이 대상이라 문장 사이에 생각할 틈이 필요하다.

eleven 은 후보에서 뺐다. `check-tts.js` 결과 이 계정 무료 플랜은 보이스 라이브러리 목소리를
API 로 쓸 수 없다(Taehyung 조회는 되지만 합성에서 막힌다). azure 는 살아 있지만 초안 단계에서
종량 과금을 쓸 이유가 없다.

### 3차 — 도식을 직접 그렸다 (가장 큰 개정)

**1·2차의 결정적 결함: 기술 설명 구간이 전부 스톡 B롤 + 글자 카드였다.** 내레이션이
"몰릴 때만 늘렸다 줄인다"라고 말하는 동안 화면에는 `stat.html` 이 "몇 분이면"이라는 큰 글자만
띄우고 있었다. **소리를 끄면 아무것도 안 남는 영상**이었다 — 클라우드 같은 개념을 설명하면서
도식이 하나도 없었다는 뜻이다.

그래서 `motion/` 에 도식 5개를 새로 그렸다(스톡에 없는 그림이라 직접 그린다 — `riversection.html`
과 같은 접근). 각각이 **글자가 아니라 그림으로** 개념을 진다.

| 도식 | 대체한 카드 | 그림이 지는 설명 |
|---|---|---|
| `cloud-rent.html` | s-def | 왼쪽 내 서버 한 대 ↔ 오른쪽 남의 건물에서 여러 대. 배치로 "빌린다"를 보인다 |
| `cloud-cost.html` | s-pay | 처음부터 높은 주황 계단 ↔ 0 에서 오르는 파란 계단. **시작점 높이**가 요점 |
| `cloud-scale.html` | s-scale | 손님 막대가 한계선(점선)을 넘으면 주황, 아래 서버가 1→5→1 로 증감 |
| `cloud-layers.html` | s-layers | 같은 5층을 세 번 그리고 **내가 맡는 칸만 주황**. 오른쪽으로 갈수록 주황이 준다 |
| `cloud-replica.html` | s-safe | 왼쪽 파일 1개에 ✕ ↔ 오른쪽 파일이 3곳으로 복제, 한 곳이 꺼져도 남음 |

`stat.html` 은 **요약 카드로만 남겼다**(s-before·s-caveat). 숫자·한 줄 각인은 stat 의 자리가 맞고,
구조·흐름·비교는 도식의 자리다.

**만들면서 프레임을 뽑아 두 번 고쳤다** — 도식은 "빌드 성공 = 잘 나옴"이 전혀 아니다.
① `cloud-scale` 의 막대가 전부 같은 높이로 나왔다(`height:100%` 인라인 + `scaleY` 애니메이션이
싸웠다 → 높이는 인라인으로 각각 주고 애니메이션은 자라는 것만 담당). ② `cloud-replica` 의
왼쪽 파일이 완전히 사라져 "무엇을 잃었는지"가 안 보였다(`vanish` 를 0.12 → 0.42 로, ✕ 를 파일
위가 아니라 옆으로). ③ 복제선이 회전을 잃었다 — 클래스의 `transform: rotate()` 를 키프레임의
`transform` 이 덮어써서다. 각도를 CSS 변수로 빼고 키프레임이 그 변수를 쓰게 고쳤다.

**5. 모션 캐시 키에 템플릿 파일명이 없어서 옛 화면이 그대로 나왔다 — 파이프라인 버그.**
도식으로 바꾼 뒤 완성본을 확인하니 `s-safe` 구간만 **예전 stat 카드**가 그대로 나왔다.
[`lib/motion.js`](../../tools/video/lib/motion.js) 의 캐시 키가 `{query, duration}` 뿐이라
**템플릿 파일명이 빠져 있었다.** `s-safe` 는 params 와 duration 이 교체 전후로 같아서
해시가 그대로였고, 낡은 렌더가 재사용됐다(나머지 4개는 params 가 바뀌어 우연히 피했다).
`isFresh` 의 mtime 비교도 낡은 렌더가 더 최신이라 통과했다.
→ 키에 `file` 을 넣어 고쳤다. **저장소 사본과 스킬 원본 두 곳 모두 고쳤다.**
이 버그의 성질이 이 영상의 교훈과 정확히 같다 — **합성은 성공하고, 프레임을 뽑기 전에는 모른다.**

## 걸린 것

**1. stat.html 의 params 이름을 지어냈다 — 조용히 사라진다.**
`label`·`note` 라는 키를 만들어 6개 카드에 넣었는데, 실제 템플릿이 받는 것은
`value`·`unit`·`title` 뿐이다. `_params.js` 는 **값이 없는 `data-p` 요소를 지워 버리므로**
잘못된 키는 오류를 내지 않고 그냥 화면에서 빠진다. 빌드는 성공하고 프레임을 뽑기 전에는 모른다.
→ **새 템플릿을 쓰기 전에 `grep -o 'data-p="[a-zA-Z]*"' <템플릿>` 으로 받는 키를 먼저 확인한다.**
`value` 는 22vh 로 아주 크게 렌더되므로 긴 문장을 넣으면 안 된다 — 짧은 말을 `value`,
꼬리를 `unit`, 설명을 `title` 로 나눈다.

**2. B롤 3개가 마지막 프레임에서 얼어붙게 되어 있었다.**
`build.js:109` 가 `clip.duration = max(선언값, 음성+0.5)` 로 늘리기 때문에, 내레이션이 길면
선언한 `duration` 과 무관하게 구간이 늘어나고 **소스 영상보다 길어지면 마지막 프레임이 정지**한다.
실측으로 잡아낸 것: `b-datacenter` +6.0s · `b-city2` +3.0s · `b-typing` +0.6s.
→ B롤 구간은 **음성 길이가 (소스 길이 − videoStart) 안에 들어오는지 먼저 계산한다.**
잘라낸 문장은 뒤따르는 stat 카드로 옮겼다 — 카드는 HTML 렌더라 길이 제한이 없다.
2차 빌드에서 해소 확인: `b-datacenter` 18.8s→13.0s(소스 13.3s) · `b-city2` 14.5s→11.3s(소스 12.0s).

**3. 초안이 5분에 한참 못 미쳤다 — 그리고 속도를 어림으로 잡으면 두 번 틀린다.**
1차 대본은 음성 합계 187.6초(+클립당 0.5s 여유 ≈ 3분 20초)로 목표의 3분의 2였다.
처음에는 "초당 5자" 라는 어림으로 1,631자를 잡았는데, **1차 실측(187.6초 / 1,189자)으로
계산한 실제 속도는 초당 6.34자**였다. 어림대로 갔으면 4분 27초로 또 모자랄 뻔했다.
→ **분량은 어림하지 말고 한 번 뽑은 음성에서 초당 글자수를 역산해 쓴다.**
`rate +6%` 기준 초당 6.3자이므로 **5분 ≈ 1,800자**(클립당 0.5s 여유 별도)다.
최종 1,822자 / 20클립 → 예상 297초. 늘리는 방법으로는 문장을 늘려 때우는 대신
6장(안전·백업)을 새로 만들었다 — 입문자가 실제로 묻는 질문이라서.

**4. 다른 세션의 빌드와 동시에 돌았다.**
`scenes.pipeline.json` 빌드가 같은 시각에 돌아 CPU 를 나눠 쓰는 바람에 모션 프레임 굽기가
클립당 2분 넘게 걸렸다(18클립 = 30분 이상). 영상 id 가 달라 파일은 안 섞였지만
(스킬 규약대로) **체감 속도는 절반 이하로 떨어진다.** 모션 위주 영상은 프레임 캡처가
대부분의 시간을 먹으므로 다른 빌드와 겹치지 않게 돌리는 편이 낫다.

**6. 합성 도중 빌드가 조용히 죽었다 — 깨진 mp4가 남는다.**
도식 포함 빌드가 합성 단계에서 **오류 한 줄 없이** 끊겼고, `final/` 에는 1MB 짜리
`moov atom not found` 파일이 남았다. 로그만 보면 "3단계 합성" 에서 멈춘 것으로 보일 뿐
실패인지 진행 중인지 구분이 안 된다. 당시 디스크가 98%(13GB) 였다.
→ 중복 렌더를 정리(230MB→141MB)하고 `--only compose` 로 다시 돌려 성공했다.
**합성이 끝났다는 말은 로그가 아니라 `ffprobe` 로 확인한다** — 깨진 파일도 파일은 남는다.
