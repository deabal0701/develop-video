## 제작

"restapi에 대한 5분 개념" 요청. 질문 라운드에서 사용자가 고른 값: **강의 · 타이포·도식
모션만 · 남성 edge 목소리 · BGM 없음**. 대상은 API라는 말은 들어봤지만 REST가 뭔지 모르는
입문 개발자·비개발 직군으로 잡았다.

**컨셉은 video-concept 워크플로로 검증했다** (13 에이전트 · 337k 토큰 ·
`.claude/debate-logs/rest-api-lecture-concept.md`). 3안 중 **"DELETE 한 줄"**(시각 충격)이
유일하게 치명·주요 지적 0건으로 확정 — 오프닝에서 살아 있는 사용자 카드에
`DELETE /users/1`이 타이핑되고, 엔터와 함께 카드가 조각으로 부서져 `204 No Content`만
남는다. 이 한 줄의 세 조각(동사·주소·대답)이 곧 목차가 되고, 엔딩에서 `GET /users/1 → 404`로
회수한다 — 지워진 것을 조회하면 404가 나온다는 것을 시청자가 방금 배운 것으로 스스로 읽는
학습 확인 장치다. 차점안("REST는 설치 불가")의 "REST는 기술이 아니라 약속" 프레임을
아웃트로에 병합했다.

구성: 훅(2.8s 무내레이션) → 훅 해설(rest-line) → 4장(주소는 명사 / 동사는 메서드 /
대답은 숫자 / 무상태) → 회수(rest-line 재사용) → 아웃트로. 장마다 chapter 카드 + 전용 도식.

**기존 api-lecture 와는 별개 프로젝트다** — 그쪽은 API 일반 기초를 실화면 데모(TodoStore
콘솔)로 찍은 강의고, 이쪽은 REST 설계 원칙을 도식만으로 설명한다. 상태코드 수치(200·204·
404·500)의 저장소 근거로 api-lecture/demo-api/server.js 를 공유한다(204: L115 · 404: L137 ·
200: L141 · 500: L126). **`/users/1` 경로 자체는 demo-api 에 없는 표준 관례 예시다** —
수치가 아니라 경로라 근거 원칙 위반은 아니라고 판단했고, 여기 명기해 둔다.

두 번 쓰이는데 말 속도가 달라 **지연을 t1·t2·t3·tn params 로 받게 했다.**

## 걸린 것

**1. preflight 가 전용 템플릿을 "없다"로 오탐하는 버그 — 파이프라인 수정.**
`lib/preflight.js` 가 공용 `motion/` 만 보고 템플릿 존재를 판정해서, `projects/<id>/` 전용
도식이 전부 "템플릿이 없다" 오류가 될 상태였다(compose 의 resolveMotionFile 은 대본 폴더를
먼저 본다 — 판정과 실행의 순서가 달랐다). **projectDir 를 먼저 찾도록 저장소 사본과 스킬
원본 두 곳을 고쳤다.** 전용 템플릿을 처음으로 대량(6장) 쓴 영상이라 이제야 드러났다.

**2. 템플릿 스크립트에서 `q.get(변수)` 를 쓰면 preflight 에 걸린다 — 의도된 동작.**
rest-line 의 타이밍 params 를 `for (k of [...]) q.get(k)` 로 읽었더니 preflight 가
"받지 않는 params" 오류를 냈다. preflight 는 리터럴 `.get('이름')` 패턴만 인식한다.
**전용 템플릿의 params 는 리터럴로 읽는다** — `{ t1: q.get('t1'), ... }`.

**3. fadeUp 키프레임이 transform 을 덮어쓴다 — 또 걸렸다.**
`translateX(-50%)` 가운데 정렬 + fadeUp 을 같이 쓰면 애니메이션이 끝나는 순간 translateX 가
사라져 오른쪽으로 튄다(cloud-replica 의 rotate 와 같은 원리). 204 문구가 실제로 밀려
나온 것을 프로토 렌더에서 잡았다. **가운데 정렬은 left/right:0 + text-align 으로 한다.**

**4. 분량 — 1차 실측 255.7s 로 39초 부족.** plan.md 에서 1,821자를 배분했는데 InJoon +6% 는
초당 약 5.9자로 선희(6.3자)보다 느리게 나왔다. 문장 부풀리기 대신 내용을 더해 보강
(주소의 계층 읽기 · 일상 속 200 · 무상태→확장 근거 · 차점안 병합 마무리) → 2차 290.6s.
**남성 InJoon rate +6% ≈ 초당 5.9자, 5분 ≈ 1,750자.**

**5. 기본 Node 가 14 라 Playwright 가 안 돈다.** `~/.nvm/versions/node/v22.19.0/bin/node` 로
실행해야 한다. check-tts 의 azure·eleven "fetch is not defined" 실패도 같은 원인(구형 Node 에
fetch 없음) — 키 문제가 아니다.

**6. 빌드 중 다른 Chromium 을 띄우면 프레임 캡처가 타임아웃으로 죽는다.**
1차 본 빌드가 s1 프레임 캡처에서 `page.screenshot: Timeout 30000ms` 로 실패했다 — 검증용
프로토 렌더 3개(각각 Chromium)를 빌드와 동시에 돌린 시점과 정확히 겹친다. cloud-lecture 의
"다른 빌드와 겹치지 않게"가 **프로토 렌더에도 적용된다.** 굽기 전 검증은 빌드 시작 전에
끝내거나, 빌드 후 캐시로 한다. `--only compose` 재개로 캐시를 살려 이어 갔다.

**7. 훅 플래시가 stage 안에 있으면 좌우에 검은 띠가 남는다.**
`.flash` 를 `.stage`(좌우 14% 여백) 안에 뒀더니 화이트 플래시가 중앙 72%만 덮었다 —
완성본 프레임(t=1.05)에서 발견. 전체 화면을 덮는 오버레이는 stage 밖, body 직속에 둔다.
아웃트로 제목도 공용 outro 의 좌우 26% 여백에 긴 제목("주소는 명사 · …")이 어색하게
꺾여, "주소 · 동사 · 대답"으로 줄이고 매핑은 subtitle 로 내렸다. 둘 다 `--only compose` 로
해당 클립만 재렌더해 해결.
