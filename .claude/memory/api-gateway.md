## 제작

`develop-lecture` 스킬로 만든 **테스트 1편**. 사용자가 "3분 이내"를 지정해 강좌 기본 5분 대신
3분 형식으로 갔다(내레이션 999자 → 실측 2분 40초).

**단발이지만 강좌 형식을 그대로 썼다** — course-intro 타이틀 카드 + course-stinger 3초
시그니처 + 챕터 카드 3장. 시리즈로 키우면 `projects/<강좌id>/` 와 `<강좌id>-NN/` 으로 쪼개면
되고, 지금은 `projects/api-gateway/` 한 폴더에 강좌 파일과 회차 파일이 같이 있다.
`num`(n강) 은 비워 뒀다 — 존재하지 않는 강좌의 1강처럼 보이지 않게 하려고.

**컨셉은 "앱이 아는 주소는 하나뿐"이다.** 장바구니 화면 뒤에 서버 여섯 대가 있는데 앱은 주소를
하나만 안다는 반전으로 열고, 아웃트로에서 그 하나에 `API Gateway` 이름표를 붙여 회수한다.
훅에서 정답(게이트웨이)을 미리 말하지 않는 것이 핵심이라, 문은 promise 구간에서야 등장한다.

**설명 구간은 전부 자작 도식 7장**이고, 실사는 규격대로 **인트로 1개만** 쓴다.

처음에는 실사 없이 갔다 — 보유 B롤이 해안 항공샷·상어뿐이라 주제와 안 맞았기 때문이다
(파일명 `road-drone.mp4` 는 실제로는 해안 파도다). 그런데 그러면 스킬 인트로 규격의 첫 칸이
비고, 검은 화면에서 제목 카드로 곧장 시작한다. 2차에서 **Pexels 에서 직접 받아 채웠다** —
검색 API 는 안 붙어 있지만 다운로드는 직접 링크만 있으면 되고, 링크는 웹에서 찾으면 된다.
후보 둘을 받아 프레임을 비교해 골랐다: 데이터센터 항공샷은 초록 들판·대낮이라 어두운 남색 덱과
충돌했고, `cables-blue`(파란 조명 아래 네트워크 케이블)는 브랜드색과 맞고 "요청이 지나는 길"
이라는 주제와 직결이라 이쪽을 택했다.

용어 주석은 3개(상한): API Gateway(s1) · Routing(s2) · Rate Limiting(s3). TTS 가 «에이피아이»로
읽어 자막만 보면 철자를 알 수 없으므로 화면이 원어를 대신 알려 준다.

## 걸린 것

**① TTS 페이스가 구간마다 크게 다르다 — 6.4자/초는 평균일 뿐이다.**
설계는 전부 6.4자/초로 역산했는데 실측은 **훅 5.1 · 아웃트로 5.1 · 본문 6.8~7.0자/초**였다.
짧은 문장이 많은 구간일수록 TTS 의 문장 간 호흡이 붙어 느려진다. 그대로 두었으면 s2·s3 의
마지막 `note` 가 **클립 길이를 넘겨 아예 안 나올** 뻔했다(29.5s 지연 vs 29.49s 클립).
→ `--only tts` 실측 뒤 구간별 배율(x0.90~x1.25)로 모든 `animation-delay` 를 재계산했다.
**다음 회차에서도 대본을 고칠 때마다 다시 재야 한다.** 각 도식 머리말에 실측값을 적어 뒀다.

**② `animation-delay` 를 규칙 두 개로 나눠 쓰면 뒤 규칙이 앞을 통째로 덮는다.**
`gw-route.html` 의 주문 서버 2·3 은 "등장"과 "점멸" 두 애니메이션이 필요했는데 `.r2`·`.b2` 로
규칙을 나눴더니 특정도가 같아 나중 것(`animation-name: hit`)이 이겨서 등장이 사라졌다.
→ 쉼표로 `animation-name: fadeUp, hit` 처럼 한 규칙에 묶는다.

**③ 고정 높이가 그리드 자식을 옆 칸으로 흘려보낸다 — 그리고 조용히 가려진다.**
`.lane { height: 8.2vh }` 에 3행짜리 주문 서버 pool 이 안 들어가 3행이 아래 `/products` 차선으로
넘쳤고, DOM 뒤쪽인 "상품 서버"가 그 위를 덮어 **"주문 서버 3"이 통째로 사라졌다.** 렌더는
성공했고 프레임을 뽑기 전까지 몰랐다. → `min-height` 로 바꿔 차선이 내용만큼 자라게 했다.

**④ 접히는 목록은 자리까지 없애야 한다.** `gw-single.html` 에서 주소 목록을 `opacity`+`scaleY`
로만 접었더니 안 보이는데 높이는 그대로라 상자 안에 빈 구멍이 남았다. → `max-height` 를 함께
0으로 줄인다.

②③④ 는 전부 **오류를 내지 않는** 종류다. 빌드가 도는 동안 렌더된 클립에서 프레임을 뽑아
본 덕에 완성 전에 잡았다 — develop-video 의 "빌드 도는 동안이 검증 시간" 규칙이 실제로 값을 했다.

**⑤ 훅을 규격보다 5배 길게 써서 시그니처가 영상 중간에 떴다 (1차의 가장 큰 실수).**
develop-lecture 인트로 규격은 `B롤 2s → 제목 4s → 훅 3~4s → 스팅어 3s` 인데, 훅에 90자를 넣어
17.7초가 되는 바람에 스팅어가 **21.7초**에 떴다. 사용자가 "갑자기 중간에 강좌명이 나온다"고
지적해서야 드러났다 — 규격 위반인데 preflight 도 못 잡고 프레임 검증도 통과한다.
원인은 훅에 "주제 소개"까지 실은 것이다. 제목 카드가 이미 주제를 말했으므로 훅은
**"왜 봐야 하나"(대비 한 방)만** 담당해야 한다. 25자로 줄여 4.03초를 맞췄고 스팅어는 **10.5초**로
올라왔다. 덜어낸 설명은 promise 로 옮겼다(13.0초 → 22.0초).

**⑥ 구간 길이를 바꾸면 그 구간의 도식은 반드시 다시 짠다.** 훅을 17.7→4.5초로 줄이자 기존
훅 도식의 지연(최대 15.5초)이 전부 클립 밖으로 나가 **아무것도 안 뜨는** 상태가 됐고,
promise 는 반대로 22초로 늘어 앞 12초가 빈 화면이 됐다. 둘 다 새로 그렸다.
